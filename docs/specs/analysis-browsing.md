# Spec — analysis-browsing

> PRD 기능 5. 전체 분석 목록 + 가맹점별 이력 타임라인.

## Problem Statement

심사자는 지금까지의 모든 분석을 한곳에서 훑어보고, 위험한 것·아직 결정 안 한 것을 빠르게 찾고 싶다. 또 특정 가맹점이 과거에 어떤 판정을 받아왔는지(처음엔 거절이었다가 보완 후 승인됐는지 등)를 시간순으로 보고 싶다. 기록이 쌓여도 흩어져 있으면 감사가 불가능하다.

## Solution

분석 목록 화면은 모든 분석을 최신순으로 보여주고, 위험등급·권고·상태로 정렬·필터할 수 있다. 각 행에서 가맹점·종합등급·AI 권고·사람 최종결정·상태가 한눈에 보이고, 클릭하면 상세로 간다. 가맹점 이력 화면은 한 가맹점의 모든 분석을 시간순 타임라인으로 보여줘, 그 가맹점의 위험 변화를 추적할 수 있다.

## User Stories

1. As a 심사자, I want 모든 분석을 최신순 목록으로 보기, so that 전체 진행 상황을 파악한다.
2. As a 심사자, I want 목록에서 각 분석의 가맹점·종합등급·권고·최종결정·상태를 보기, so that 열어보지 않고도 핵심을 안다.
3. As a 심사자, I want 위험등급으로 필터하기, so that 고위험 건만 모아 본다.
4. As a 심사자, I want 권고(승인/거절/추가정보)로 필터하기, so that 특정 권고 건만 확인한다.
5. As a 심사자, I want 상태(대기/실행중/완료/실패)로 필터하기, so that 처리할 대기·실패 건을 찾는다.
6. As a 심사자, I want 아직 사람 최종결정이 안 된 건을 가려내기, so that 내가 결정해야 할 일을 놓치지 않는다.
7. As a 심사자, I want 목록 행을 클릭하면 분석 상세로 가기, so that 바로 검토·결정한다.
8. As a 심사자, I want 한 가맹점의 모든 분석을 시간순으로 보기, so that 그 가맹점의 위험 변화를 추적한다.
9. As a 심사자, I want 가맹점 이력에서 각 분석의 날짜·등급·권고·최종결정을 보기, so that 재심사 흐름(거절→보완→승인 등)을 이해한다.
10. As a 심사자, I want 가맹점 이력에서 특정 분석을 클릭해 상세로 가기, so that 과거 판정의 근거를 확인한다.
11. As a 심사자, I want 가맹점 이력 화면에서 "새 분석(재심사)"을 시작하기, so that 그 가맹점을 다시 심사한다.
12. As a 심사자, I want 목록이 비었을 때 안내가 보이기, so that 무엇을 해야 할지 안다.

## Implementation Decisions

- **분석 목록 화면**: `/analyses` (Presentation). `GET /api/analyses`로 전체 분석(조인된 가맹점명·업종, 종합등급·권고·상태·최종결정·생성일) 최신순 조회. 정렬/필터는 클라이언트에서(등급·권고·상태·미결정 여부). 행 클릭 → `/analyses/[id]`.
  - 응답 항목에 `final_decision` 포함시켜 "미결정"(`completed`이나 `final_decision IS NULL`) 구분 가능하게 한다.
- **가맹점 이력 화면**: `/merchants/[id]` (Presentation). `GET /api/merchants/[id]` → 가맹점 정보 + 그 가맹점의 분석 배열(시간순). 타임라인 형태로 각 분석의 생성일·등급·권고·최종결정 표시, 클릭 시 상세 이동. "재심사" 버튼은 `merchant-intake`의 생성 경로 재사용.
- **API 추가/조정**:
  - `GET /api/analyses` — 목록(가맹점명·업종·등급·권고·상태·`final_decision`·생성일). sample 기준에 `risk_grade`/`recommendation`/`final_decision` 컬럼 추가 반영.
  - `GET /api/merchants/[id]` — 가맹점 + analyses 이력(신규).
- **표시**: 등급/권고/상태/최종결정은 `Badge`로 색 구분. 미결정 건은 시각적으로 강조(대시보드 KPI와 일관된 의미).
- **필터 상태**: URL 쿼리 또는 로컬 상태로 유지(새로고침 시 합리적 기본값). 구현 단순성 우선.

## Out of Scope

- 분석 생성/실행/결정(다른 기능).
- 가맹점 정보 편집/삭제.
- 페이지네이션·검색(데이터 규모가 작은 로컬 도구이므로 전체 로드 + 클라이언트 필터로 충분; 대량화는 v1 제외).
- CSV 내보내기(개별 보고서 인쇄는 상세 화면 담당).

## Further Notes

- 목록과 타임라인은 같은 `analyses` 데이터를 다른 축(전체 vs 가맹점별)으로 보는 두 뷰다.
- "미결정 대기"의 정의(완료됐으나 사람 결정 전)는 `dashboard` KPI와 동일하게 맞춘다.
